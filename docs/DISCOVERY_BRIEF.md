# Discovery Brief：企业知识库问答闭环

> 这是一个基于脱敏样例和本地验证证据的 FDE 需求发现简报，不代表已经服务真实客户。

## 1. 业务问题

企业资料分散在 PDF、Word、Markdown 等文件中，后续还可能接入表格和 OA/CRM/ERP。员工希望用自然语言找到可信答案，但管理员必须控制“谁能看到什么”，并能够解释答案来源、失败原因和运营成本。

## 2. 用户与工作流

| 用户 | 主要任务 | 最小成功结果 |
|---|---|---|
| 知识管理员 | 上传、替换、停用、重建文档，配置 ACL | 文档进入 `ready`，权限和版本可追踪 |
| 员工 | 登录、提问、查看引用、反馈 | 只得到有权访问资料中的答案或明确拒答 |
| 审计/运营人员 | 查看拒绝、延迟、失败、Token 和反馈 | 能定位问题而不读取普通用户问题正文 |
| 集成方 | 调用只读 Tool/MCP | 只能发现和执行批准的只读能力 |

## 3. 约束

- 现有主项目是 Java/Spring Boot + Flutter，不能为了 AI 框架重写企业后端。
- 权限必须在服务端和检索查询阶段执行。
- 本地 Provider 可能超时、截断 JSON 或记录请求，不能直接假设生产安全。
- 需要低成本、可本地复现、可用 Docker Compose 启动的交付形态。
- 没有真实客户数据时，不承诺准确率、并发量或 ROI。

## 4. V0.1 成功指标

### 已有可验证门槛

- Golden Dataset：20 个版本化问题，数据契约检查通过。
- Retrieval Stress：8 个压力问题，历史真实基线达到 8/8，ACL leakage=0。
- ACL：跨租户、未授权文档和身份参数覆盖拒绝，ACL leakage=0。
- 后端回归：本地 Docker-backed `./mvnw test` 109 tests，0 failures/errors/skipped。
- MCP 边界：本地只读 HTTP smoke 16/16 checks 通过。

### 尚不能当作承诺的指标

- 真实客户准确率、长期反馈率、并发量、SLA 和 ROI。
- 当前本地模型的稳定答案质量；独立 Structured Output 探针仍未通过能力门禁。
- 云端成本；当前成本只是可配置估算，不等同 Provider 账单。

## 5. 非目标

Fine-tuning、GraphRAG、Neo4j、复杂 Multi-Agent、Kubernetes、GPU 采购、未经审批的写操作和全量 Python 重写均不在本阶段范围内。

## 6. 交付前需要客户确认的问题

1. 文档来源、更新频率、保留周期和敏感等级是什么？
2. 用户、部门、角色与知识库/文档 ACL 如何映射？
3. 哪些问题必须拒答并转人工？
4. Provider 请求日志是否允许落盘，保留多久，谁可访问？
5. 成功标准优先是找回率、回答完整性、响应时间、成本，还是人工工时减少？
6. 哪些 Tool 可以只读，哪些操作必须人工审批？
