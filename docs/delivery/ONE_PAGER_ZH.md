# 企业知识库问答系统 — 一页说明

一套让员工按权限提问、答案带出处、资料不足就拒答而不是瞎编的企业知识库问答系统。本地可部署，数据可以不
出内网。

## 解决什么问题

把公司制度、产品手册、售后 FAQ 接入 AI 问答之后，企业真正会问的是：

- 员工会不会看到不该看的资料？
- 答案从哪来的，模型会不会编造出处？
- 资料里没有的问题，AI 会不会凭常识乱答？
- 权限被收回之后，之前的对话还能不能继续套出旧答案？
- 答得好不好、快不快、成本多少，拿什么衡量？

## 交付范围

| 包含 | 可选 | 不承诺 |
|---|---|---|
| 文档接入（PDF/Word/Markdown），版本化、可重建索引 | 本地模型部署（数据不出内网） | AI 百分之百正确——系统设计为资料不足时拒答并转人工 |
| 按部门/角色/文档的访问权限，权限变更带审计 | 云端模型（已实测 DeepSeek，质量更高、延迟更低） | 不经客户自己数据验证的固定准确率数字 |
| 带出处引用的问答，引用由后端校验，不是模型自说自话 | 独立的 Python Agent 层（多步工具调用、对话记忆、MCP 接入） | 生产级 SLA（当前是可复现的本地/演示部署，非公开生产运行） |
| 管理端（上传、权限、索引状态）、部署与数据处理文档 | | |

## 怎么验收

不需要只相信我们报告里的数字——验收手册里有一套可以直接用**你自己的文档和问题**跑的评测流程，权限隔
离、资料外拒答、引用核实、撤权测试都有明确的"怎么测、预期什么结果"。详见
[验收评测手册](ACCEPTANCE_HANDBOOK.md)，数据会发给谁、存在哪里、保留多久见
[数据处理说明](DATA_HANDLING.md)。

## 技术要点

Java 17 / Spring Boot + PostgreSQL（pgvector）+ Flutter 客户端；权限在 SQL 检索语句里过滤，不是界面层
过滤；引用由后端生成和校验，模型输出不合规一律转人工。评测方法论、工具调用可靠性、成本延迟对比等工程
证据见验收手册第5节。

## 开发方式

实现代码主要由 AI 编码代理（OpenAI Codex、Claude Code）编写，需求、架构、评测设计、代码评审与验收决策
由本人负责。完整背景见 [PORTFOLIO.md](../../PORTFOLIO.md) 和 [Case Study](../CASE_STUDY.md)。
